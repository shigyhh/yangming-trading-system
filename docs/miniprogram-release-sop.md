# 小程序体验版与发布 SOP

目标：让小程序后续更新保持轻、稳、可追踪。小程序负责稳定壳层和交互，服务器负责训练内容、K线数据、复盘同步、活镜档案和配置开关。

## 版本分层

```text
Dev 版：本地开发和模拟器调试
体验版：内部真机闭环测试
审核版：提交微信审核的候选版本
正式版：审核通过后发布给用户
```

## 分支规则

发布运作类改动使用独立分支，例如：

```bash
feature/miniapp-launch-0
```

业务功能不要混进发布分支。K线、真实复盘、支付、首页视觉、server provider/backfill 都应走各自功能分支。

## 每次体验版上传前

1. 确认当前分支不是 `main`。
2. 确认 `git status --short` 只包含本次要上传的改动。
3. 运行小程序相关测试。
4. 确认 release 环境 API base 指向：

```text
https://xxjyxt.com
```

5. 确认微信小程序后台已配置 request 合法域名：

```text
https://xxjyxt.com
```

6. 确认本轮没有出现投资建议、行情预测、收益承诺、具体买卖点。

## 体验版上传

在微信开发者工具中执行：

```text
上传
↓
填写版本号和备注
↓
小程序后台生成体验版
↓
内部成员真机扫码测试
```

建议版本备注格式：

```text
v0.1.0-exp.1：首页 + 真实复盘 + K线观心最小闭环
v0.1.0-exp.2：修复 K线训练同步状态
v0.1.0-rc.1：提审候选版本
```

## 真机验收

体验版必须按 `docs/miniprogram-experience-checklist.md` 跑一遍。模拟器通过不等于真机通过。

## 提交审核前

1. 真机主链路通过。
2. 合规说明可见。
3. 隐私协议、服务类目、备案信息、合法域名都已在微信后台配置。
4. 服务器 smoke 通过：

```bash
curl -sS "https://xxjyxt.com/api/v1/kline-history/slice?market=cn_equity&symbol=600519&timeframe=30m&window=80&blind=0&mode=step_replay"
```

5. 本轮新增页面或入口已确认不涉及未申报类目。

## 正式发布后

1. 先小范围观察。
2. 记录首日问题：打不开、请求失败、同步失败、路径迷失、合规风险。
3. 内容、K线缓存、训练文案优先通过服务器更新。
4. 页面结构、入口、新流程、权限变更再发小程序新版本。

## 后续更新原则

适合服务器更新：

```text
今日训练内容
K线 slice 数据
训练场景元数据
真实复盘同步结果
活镜成长档案
合规说明文本版本
灰度开关
```

适合小程序发版：

```text
新页面
新 tab
新按钮
新表单
新权限
新本地存储结构
关键交互流程变化
```

## 回退方式

如果新体验版有问题：

1. 不提交审核。
2. 继续上传修复后的体验版。
3. 已上线正式版发现阻断问题时，在微信后台回退到上一个稳定版本，并同时修复下一版。

如果只是服务器内容或数据问题：

1. 优先修服务器。
2. 保持小程序版本不动。
3. 用真机重新验证接口和页面展示。
