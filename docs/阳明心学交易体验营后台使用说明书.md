# 阳明心学交易体验营后台使用说明书

适用后台：`/admin/ymty/`

适用对象：运营、助教、售后、管理员

版本说明：本说明书按当前体验营后台的“运营工作台”结构整理。后台用于管理课程展示配置、活码池、私域承接、客户跟进、订单售后和操作日志；真实支付金额以后端订单为准。

后台右上角也提供“使用说明”按钮，可在不离开当前页面的情况下打开内置说明抽屉。

## 1. 后台入口与登录

后台地址：

`https://xxjyxt.com/admin/ymty/`

本地预览地址：

`http://127.0.0.1:8790/admin/ymty/`

注意：

- 不要直接用 `file://.../web-mvp/admin/ymty/index.html` 打开后台，否则浏览器会拦截 API 请求，容易出现 `Failed to fetch`。
- 管理员账号和初始密码由部署环境变量配置，不写在代码里。
- 登录令牌只保存在当前浏览器会话中，关闭标签页或退出登录后会失效。
- 首次登录后如系统要求修改密码，应先完成修改。

## 2. 后台导航结构

后台顶部按运营工作流分为 6 个入口：

| 模块 | 用途 |
| --- | --- |
| 运营首页 | 看今日状态、待办、数据漏斗、产品配置 |
| 活码池 | 上传二维码、批量新增活码、查看可分配状态 |
| 私域承接 | 查看 paid 后用户如何进入助教承接链路 |
| 客户跟进 | CRM 阶段看板、客户备注、负责人和跟进状态 |
| 订单售后 | 订单查询、退款申请、退款演练与审核状态 |
| 系统记录 | 审计日志、账号安全相关操作记录 |

建议日常使用顺序：

1. 先看“运营首页”的健康状态和今日待办。
2. 如果提示无可用活码，进入“活码池”处理。
3. 如果有待跟进客户，进入“客户跟进”处理。
4. 如果有退款待审，进入“订单售后”处理。
5. 涉及责任追溯时，再查看“系统记录”。

## 3. 运营首页

运营首页用于回答三个问题：

- 今天能不能报名付款？
- 支付后能不能分配助教入口？
- 是否有售后、退款或客户跟进待处理？

主要区域：

| 区域 | 看什么 | 怎么处理 |
| --- | --- | --- |
| 运营健康状态 | 课程上架、助教入口、今日支付、企微同步、退款开关、二维码曝光、跟进数据 | 有红色或异常提示时，优先处理 |
| 今日待办 | 收款开关、助教入口、客户跟进、退款审核、企微同步、今日漏斗 | 点击对应卡片进入处理模块 |
| 数据概览 | 访客、报名点击、创建订单、支付成功、支付金额、二维码曝光、获客链接点击 | 用来判断投流和承接效果 |
| 转化漏斗 | 访问 → 报名 → 下单 → 支付 → 二维码曝光 → 加微点击 | 看到掉点后再查对应模块 |
| 产品与价格 | 上架状态、展示价格、实际支付金额、训练周期、开课时间、主讲人 | 只在需要调整活动信息时修改 |

重要提醒：

- 前端展示价格只用于展示，真实支付金额以后端订单为准。
- 修改价格只影响新订单，旧订单金额不会被覆盖。
- 修改价格属于敏感操作，保存前应二次确认。

## 4. 产品与价格

进入位置：

`运营首页 → 产品与价格`

可维护内容：

| 字段 | 说明 |
| --- | --- |
| 产品编码 | 固定为体验营产品编码，只读 |
| 上架状态 | 上架 / 下架 |
| 产品名称 | 前端展示课程名称 |
| 展示价格（元） | 落地页显示价格 |
| 实际支付金额（分） | 后端创建订单时使用的真实金额 |
| 训练周期 | 例如 7天训练 |
| 开课时间 | 例如 每周滚动开营｜晚20:00 |
| 主讲人 | 前端展示主讲人 |

操作建议：

- 只在活动信息确定后修改。
- 价格调整前先确认是否影响投流素材、落地页文案和客服口径。
- 下架后用户不能正常报名，但历史订单和已支付入口不应因此失效。

## 5. 活码池

活码池是 paid 后分配助教入口的核心模块。

进入位置：

`活码池`

### 5.1 活码池顶部状态

顶部只看 4 类状态：

| 状态 | 含义 |
| --- | --- |
| 可分配活码 | 当前可以分配给新 paid 订单的活码数量 |
| 承接入口 | 有二维码或获客助手链接的入口数量 |
| 满员 / 停用 | 不参与新订单分配的活码数量 |
| 分配规则 | 当前按优先级和最少分配进行轮询 |

### 5.2 活码筛选

活码卡片支持筛选：

| 筛选 | 用途 |
| --- | --- |
| 全部 | 查看当前池内所有活码 |
| 可分配 | 当前会参与新订单分配 |
| 待处理 | 启用但没有二维码和获客助手链接，需要补入口 |
| 满员 | 人工标记满员，不再分配新订单 |
| 停用 | 已停用，不再分配新订单 |

### 5.3 批量添加活码

批量添加是新增活码的主入口，也支持只添加 1 张。

操作流程：

1. 点击“选择二维码”，选择 1 张或多张二维码图片。
2. 在预览列表中确认二维码能正常显示。
3. 填写同一批活码的基础信息。
4. 点击“一键保存多条活码”。
5. 保存成功后，再在卡片区确认是否变为“可分配”。

基础字段：

| 字段 | 建议 |
| --- | --- |
| 承接类型 | 个人微信或企业微信 |
| 适用渠道 | 空值或 `*` 表示全渠道；也可填 `douyin,wechat_group` |
| 获客助手链接 | 企业微信获客助手链接，可选 |
| 加微备注 | 建议保留“知行 + 手机号后4位” |
| 按钮文案 | 例如“添加课程助教微信” |
| 客服说明文案 | 成功页展示的客服说明 |

高级分配字段：

| 字段 | 含义 |
| --- | --- |
| 容量上限 | `0` 表示不限量；大于 0 表示最多分配多少订单 |
| 分配优先级 | 数字越小越优先 |
| 默认兜底 | 没有专属渠道活码时使用 |

### 5.4 分配优先级和轮询规则

后台分配逻辑可以理解为：

1. 先看订单来源渠道。
2. 如果有匹配渠道的活码，优先用渠道专属活码。
3. 如果没有匹配渠道，使用 `*` 全渠道兜底活码。
4. 排除停用、满员、容量已满、没有入口的活码。
5. 按“分配优先级”排序，数字越小越先用。
6. 同一优先级下，优先分配给“已分配数量最少”的活码。
7. 同一个订单刷新成功页时，始终返回原先绑定的活码，不会乱跳。

例子：

| 活码 | 渠道 | 优先级 | 已分配 | 结果 |
| --- | --- | --- | --- | --- |
| A | `douyin` | 50 | 3 | 抖音订单优先候选 |
| B | `douyin` | 50 | 1 | 同优先级下比 A 更先分配 |
| C | `*` | 100 | 0 | 没有专属渠道时兜底 |

### 5.5 活码卡片动作

每张活码卡片常用动作：

| 动作 | 用途 |
| --- | --- |
| 编辑 | 修改二维码、获客助手链接、备注、按钮文案、渠道、容量等 |
| 标记满员 | 临时暂停新订单分配，但不影响已分配订单 |
| 恢复分配 | 取消人工满员，让活码重新参与分配 |
| 停用 | 不再参与新订单分配 |
| 启用 | 恢复可用，前提是有二维码或获客助手链接 |

不建议物理删除历史活码，因为已分配订单刷新成功页时需要继续显示原入口。

## 6. 私域承接

进入位置：

`私域承接`

这个页面只看链路和数据，不重复配置。

支付后的承接逻辑：

1. 成功页先请求订单状态。
2. 只有订单为 `paid`，才请求助教入口。
3. 后端按活码池规则绑定一条活码。
4. 用户看到获客助手按钮或二维码。
5. 用户可点击获客助手链接，或长按二维码添加课程助教。

两个承接路径：

| 路径 | 适用场景 |
| --- | --- |
| 获客助手直达 | 企业微信链接可打开，用户可以直接进入添加或聊天 |
| 二维码兜底 | 链接不可用、微信限制、用户习惯长按识别时使用 |

建议：

- 企业微信承接建议同时配置获客助手链接和二维码。
- 个人微信承接至少配置二维码。
- 如果后续开启企业微信回调，可统计添加成功、负责人和客户阶段。

## 7. 客户与跟进

进入位置：

`客户跟进`

用途：

- 查看已支付客户当前处于哪个跟进阶段。
- 记录负责人、下次跟进时间、标签和备注。
- 人工标记客户是否已添加、已沟通、已进群、已完课、已转化或流失。

阶段看板：

| 阶段 | 含义 |
| --- | --- |
| 已支付 | 订单已支付，但可能还未完成承接 |
| 已分配助教 | 已绑定活码 |
| 已添加 | 运营确认客户已添加助教 |
| 已首次沟通 | 已完成第一次有效沟通 |
| 已进群 | 已进入课程社群 |
| 已开课 | 已开始课程服务 |
| 已完课 | 已完成课程周期 |
| 已转化 | 有后续转化 |
| 流失 | 客户未继续推进 |

操作建议：

- 每天优先处理“待跟进客户”。
- 只记录运营必要信息，不记录完整聊天内容。
- 手机号只记录后四位，便于备注核对。
- 标签用于运营分类，例如“高意向、需提醒、已进群”。

## 8. 企业微信同步

进入位置：

`客户跟进 → 企业微信同步`

功能说明：

- 默认未启用时，不影响个人微信二维码和手工承接。
- 启用后可接收企业微信客户联系事件，用于统计添加成功、负责人和来源。
- 标签同步失败不会影响客户添加链路，可在后台重试。

安全提醒：

- 后台不显示企业微信 Secret、Callback Token 或 AES Key。
- 不采集聊天正文。
- 不读取通讯录、朋友圈或会话存档。

## 9. 订单售后

进入位置：

`订单售后`

包含：

- 订单列表
- 退款控制台
- 退款申请

### 9.1 订单列表

用于查询：

| 字段 | 用途 |
| --- | --- |
| 订单号 | 售后核对 |
| 支付状态 | 判断是否 paid |
| 支付渠道 | 微信 / 支付宝 / mock 测试 |
| 金额 | 核对实付 |
| 来源渠道 | 判断投流来源 |
| 创建时间 | 排查支付和回调 |

### 9.2 退款申请

退款状态：

| 状态 | 含义 |
| --- | --- |
| requested | 已提交退款申请 |
| approved | 已通过内部审核，但不代表已到账 |
| rejected | 申请被拒绝 |
| processing | 已进入支付平台处理 |
| refunded | 支付平台明确确认退款成功 |
| failed | 支付平台明确失败 |

重要规则：

- 只有 paid 订单可申请退款。
- 退款金额不能超过实付金额。
- 审核通过不等于退款成功。
- 只有 `refunded` 才表示平台确认退款完成。
- 退款成功后可能撤销课程权益，具体以后台配置和退款规则为准。

### 9.3 退款控制台

退款控制台当前用于 Dry Run 和规则草稿。

注意：

- Dry Run 不会真实退款。
- 真实退款执行开关只能由服务器环境变量控制。
- 后台保存规则不等于开启真实退款。

## 10. 系统记录

进入位置：

`系统记录`

用途：

- 查看管理员操作日志。
- 追踪产品配置、活码、退款、CRM 等关键变更。
- 出现异常时用于定位是谁、什么时候、改了什么。

操作建议：

- 日常运营不需要频繁查看。
- 出现错误配置、退款争议、活码异常时再查。
- 不要在备注里写密码、密钥、完整客户隐私信息。

## 11. 日常运营检查清单

每天投流前：

- 课程状态是否上架。
- 展示价格和真实支付金额是否正确。
- 活码池是否至少有 1 张可分配活码。
- 成功页二维码或获客助手入口是否可用。
- 退款开关是否保持预期状态。

每天投流中：

- 访客、报名点击、创建订单、支付成功是否有数据。
- 漏斗掉点是否异常。
- 活码是否满员或停用。
- 是否有待跟进客户。
- 是否有退款待审核。

每天收尾：

- 把已添加客户标记到 CRM。
- 给需要二次触达的客户设置下次跟进时间。
- 检查操作日志中是否有异常改动。
- 确认未处理退款或同步失败任务。

## 12. 常见问题

### 后台登录显示 Failed to fetch

通常是直接用 `file://` 打开了 HTML，或本地服务没启动。

正确方式：

- 本地：`http://127.0.0.1:8790/admin/ymty/`
- 线上：`https://xxjyxt.com/admin/ymty/`

### 为什么上传二维码后还不是可分配？

需要同时满足：

- 活码状态为启用。
- 未人工标记满员。
- 容量没有达到上限。
- 至少有二维码或获客助手链接。
- 保存成功写入服务器。

### 批量添加能不能只加一张？

可以。批量添加支持 1 张或多张二维码。选择 1 张时就是新增 1 条活码。

### 兜底是什么意思？

兜底活码通常配置渠道为 `*`。当订单来源没有专属渠道活码时，系统使用兜底活码承接。

### 分配优先级是什么意思？

数字越小越优先。比如优先级 50 会先于优先级 100。相同优先级下，系统优先选择已分配数量更少的活码。

### 已分配订单会不会因为活码满员而换码？

不会。满员和停用主要影响新订单。已分配订单刷新成功页时，会优先返回原先绑定的活码。

### 私域承接页面为什么不能直接配置？

配置统一在活码池，私域承接页面只看链路和数据，避免同一个入口在多个地方重复维护。

## 13. 安全与合规提醒

- 后台只给授权人员使用。
- 不要把管理员密码、Token、密钥发到聊天工具或截图里。
- 不要在后台公开真实密钥、证书、APIv3 Key。
- 不要绕过 paid 鉴权展示二维码或获客链接。
- 不要把课程描述为荐股、喊单、跟单或收益承诺。
- 本体验营仅用于投资教育、交易纪律训练、模拟盘训练和风险意识教育。
